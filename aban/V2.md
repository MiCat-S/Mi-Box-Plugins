# Aban V2

入口为 `v2.ts`，通过 TeleBox V2 SDK 加载。原版 `aban.ts` 保留供旧运行时使用。

## 命令

| 命令 | 功能 |
| --- | --- |
| `.aban` | 查看封禁管理帮助 |
| `.kick [目标]` | 踢出，允许重新加入 |
| `.ban [目标]` | 先尝试清理当前群中该用户的消息，再封禁；分别报告结果 |
| `.unban [目标]` | 解封 |
| `.mute [目标] [时长]` | 禁言，时长如 `60s`、`5m`、`1h`、`1d`；省略为永久 |
| `.unmute [目标]` | 解除用户限制 |
| `.sb [目标]` | 在管理群组/频道中批量封禁，同时清理当前群中的目标消息 |
| `.unsb [目标]` | 在管理群组/频道中批量解封 |
| `.refresh` | 重建管理群缓存，包含归档会话 |

目标支持回复消息、`@用户名`、用户 ID；指定目标优先于回复。
例如 `.mute @username 5m`。管理员目标需在原命令后追加 `true`；确认不会提升权限。

基本群的 `ban` / `sb` / `kick` 执行移出，不阻止重新加入；解封和禁言操作会报告不支持。
管理列表沿用原版的创建者、封禁权限或删除消息权限筛选；具体操作仍由 Telegram 校验权限。

## 运行方式

- 复用登录客户端，按需加载协议库。
- 管理列表排除已退出、已停用、已升级的旧群；升级后的超级群按自身会话和权限纳入。
- 缓存保存 ID、访问哈希、名称及类型，存入插件范围的 `aban_cache.json`，五分钟后在下次使用时刷新；`.refresh` 可立即重建。
- 批量任务使用四路并发，受 V2 生命周期跟踪，卸载后停止后续请求。
- 批量封禁遇到不超过八秒的 FLOOD_WAIT 时等待并重试一次；较长限流记录为失败。
- 当前超级群消息清理持续调用接口，直到返回的 `offset` 为零；基本群会显示 `BASIC_GROUP_HISTORY_UNSUPPORTED`。
- 结果在原消息更新，批量封禁与消息清理分别显示状态和错误码，批量结果三十秒后自动删除。
- 卸载或断线无法撤销已被 Telegram 接受的操作；中断踢出时可能需手动解封。

协议依据：[群组迁移字段](https://core.telegram.org/constructor/chat)、[超级群成员消息清理](https://core.telegram.org/method/channels.deleteParticipantHistory)、[历史清理分页结果](https://core.telegram.org/constructor/messages.affectedHistory)。

## 验证

使用 Node.js 24，在插件仓库执行 `node --test scripts/aban-v2.test.js`。
测试直接提取原版业务类对照成功路径，并覆盖失效群过滤、真实 JSON 存储、缓存刷新、分页清理、错误提示及卸载取消。
测试通过 V2 PluginHost 和模拟 Telegram 客户端验证，不操作真实群成员。
构建使用主体仓库的 `scripts/build-v2-plugin.cjs`，入口为 `aban/v2.ts`。

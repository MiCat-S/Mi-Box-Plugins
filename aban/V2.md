# Aban V2

入口为 `v2.ts`，通过 TeleBox V2 SDK 加载。原版 `aban.ts` 保留供旧运行时使用。

## 命令

| 命令 | 功能 |
| --- | --- |
| `.aban` | 富文本帮助 |
| `.kick [目标]` | 踢出，允许重新加入 |
| `.ban [目标]` | 封禁，成功后按权限清理当前群中该用户的消息 |
| `.unban [目标]` | 解封 |
| `.mute [目标] [时长]` | 禁言，时长如 `60s`、`5m`、`1h`、`1d`；省略为永久 |
| `.unmute [目标]` | 解除用户限制 |
| `.sb [目标]` | 在有封禁权限的群组/频道中批量封禁 |
| `.unsb [目标]` | 在有封禁权限的群组/频道中批量解封 |
| `.refresh` | 刷新管理群缓存，包含归档会话 |

目标支持回复消息、`@用户名`、正整数用户 ID；指定目标优先于回复。
例如回复消息发送 `.mute 5m`，或直接发送 `.mute @username 5m`。
管理员目标必须在原命令后追加 `true`。Telegram 的权限规则仍然适用，确认不会提升权限。
禁止操作当前登录账号；无法确认权限的群组不执行操作。

基本群仅支持移出现有成员。`ban` / `sb` 在基本群执行移出，不阻止重新加入；
解封、禁言和解除禁言会报告不支持，不自动升级群组。
禁言时长接受 30 秒至 366 天，避免 Telegram 将超出范围的时长解释为永久。

## 运行方式

- 复用登录客户端，按需加载协议库；不安装额外依赖。
- 群缓存只保存 ID、访问哈希、名称及类型，五分钟后在下次使用时刷新，卸载即释放。
- V1 的磁盘文件仅是可再生成的群缓存，无需迁移；V2 不创建持久缓存。
- 同时只接受一个管理任务；批量任务受 V2 生命周期跟踪，卸载后不再发起后续请求。
- 请求串行执行；不超过八秒的 FLOOD_WAIT 等待后重试一次，较长限流记录为失败。
- 结果在原消息更新，显示成功、失败、不支持计数；结果保留供核对。
- 卸载或断线无法撤销已被 Telegram 接受的操作；中断踢出时可能需手动解封。

## 验证

在插件仓库执行 `node --test scripts/aban-v2.test.js`。
测试通过 V2 PluginHost 和模拟 Telegram 客户端验证，不操作真实群成员。
构建使用主体仓库的 `scripts/build-v2-plugin.cjs`，入口为 `aban/v2.ts`。
